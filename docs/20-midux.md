# Midux Theme Implementation

How Midux is built, deployed and extended.

## Project layout

```text
siyuan-theme/
├── docs/                    developer notes
├── src/
│   ├── presets/             color presets
│   │   ├── _sepium.scss
│   │   └── _steel-grey.scss
│   ├── _b3-map.scss         palette mapping
│   ├── _editor-width.scss   continuous editor padding
│   ├── _menu.scss           menu swatch style
│   ├── _opaque-layers.scss  subpixel text fixes
│   ├── _preset.scss         preset() mixin
│   ├── _ui-font.scss        UI font sizes
│   └── theme.scss           entry point
├── theme/                   the installable theme package
│   ├── theme.css            GENERATED by Sass
│   ├── theme.js             preset menu (hand-written)
│   └── theme.json
├── .editorconfig            editor formatting rules
├── .env.example             template for the local .env
├── .gitignore
└── justfile                 build and deploy recipes
```

- `theme/` holds exactly what SiYuan needs. Deployment links or copies only this folder.
- **_Never edit `theme/theme.css` by hand._** The next build overwrites it.

## Requirements

- **Dart Sass**, as a `sass` command on your `PATH`. For example: `npm install -g sass`.
- **just**, to run the recipes.

**SCSS** is used instead of **Less** because:

- SiYuan's own styles are SCSS.
- Dart Sass has a built-in watch mode.
- No need for project-level Node setup.

**just** is used instead of **npm scripts** because:

- The project needs no `package.json` and no `node_modules`. The repository stays plain source files plus the theme package.
- Recipes are plain shell, and multi-line recipes run as Bash scripts, which suits the link and install logic.
- It loads `.env` by itself (`set dotenv-load`), and recipe variables can be overridden from the command line.
- `just --list` documents every recipe.

## Development workflow

All tasks are recipes in the `justfile`. Run `just --list` to see them.

### Configuration

The target workspace comes from `SIYUAN_WORKSPACE`. Copy `.env.example` to `.env` and set your path. `.env` is git-ignored.

| Source         | Example                                | Priority |
| -------------- | -------------------------------------- | -------- |
| Command line   | `just ws="$HOME/SiYuan/Other" link`    | Highest  |
| Shell variable | `SIYUAN_WORKSPACE=… just link`         | High     |
| `.env` file    | `SIYUAN_WORKSPACE="…/Master Vault"`    | Medium   |
| Default        | `~/SiYuan` (SiYuan's default on Linux) | Lowest   |

> [!note]
> Inside `.env`, `$HOME` in double quotes is expanded, but `~` is not.

### Build

| Recipe       | Action                                             |
| ------------ | -------------------------------------------------- |
| `just build` | Compile `src/theme.scss` to `theme/theme.css` once |
| `just watch` | Recompile on every save                            |

- `sass --watch` follows every `@use`, so editing any partial recompiles.
- A new partial is watched once a watched file references it with `@use`.
- Source maps are off (`--no-source-map`), which keeps the theme folder clean.
- Each compile rewrites `theme.css` in place, which triggers SiYuan's live reload.

### Deployment

| Recipe         | Action                                                          |
| -------------- | --------------------------------------------------------------- |
| `just link`    | Build, then symlink `theme/` to `<workspace>/data/themes/Midux` |
| `just install` | Build, then copy `theme/` there as a real folder                |
| `just remove`  | Remove the symlink or the copied folder                         |
| `just status`  | Show whether the theme is linked, copied or missing             |

- **Link** is for development. SiYuan follows the folder symlink, so live reload works. Symlinks are not synced.
- **Install** is for daily use. The copy syncs to your other devices.
- `link` refuses to replace a copied folder. Run `just remove` first.

First-time setup:

1. Run `just link`.
2. Restart SiYuan so it finds the new theme.
3. Choose **Midux** as the light theme in Settings → Appearance.

> [!tip]
> **Testing checklist**
>
> 1. `just link`, restart SiYuan and select Midux.
> 2. Open the sun menu: Sepium (selected) and Steel Grey appear below a separator.
> 3. Select Steel Grey: the background changes immediately.
> 4. Restart SiYuan: Steel Grey is still active, and `data/storage/local.json` contains `midux-preset`.
> 5. Switch to another theme and back: the DevTools console shows no errors.
> 6. Run `just watch` and edit a preset color: SiYuan updates without a restart.

## Notable theme features

### Color presets

Presets are selectable in the Appearance Mode menu (sun icon). Each preset is one SCSS partial.

#### Palette and mapping

The CSS has two layers:

- **Palette:** each preset defines `--mx-*` variables, based on the VS Code preview theme palette.
- **Mapping:** `_b3-map.scss` points SiYuan's `--b3-*` variables at the palette, once for all presets.

```scss
// src/presets/_sepium.scss: the palette
@include preset("sepium", $default: true) {
  --mx-bg-primary: #f3f2ee;
  --mx-text-normal: #1e1e1e;
}

// src/_b3-map.scss: the mapping, shared by all presets
:root {
  --b3-theme-background: var(--mx-bg-primary);
  --b3-theme-on-background: var(--mx-text-normal);
}
```

`var()` resolves on `<html>`, so the mapping always follows the active preset.

The `--mx-` prefix avoids collisions with SiYuan and plugin variables.

#### The preset() mixin

```scss
@include preset("steel-grey") {
  --mx-bg-primary: #eff1f3;
}
```

- It wraps the block in `:root[data-midux-preset="<name>"]`.
- With `$default: true`, it also applies on plain `:root`. The theme then looks right before `theme.js` runs.
- It also applies on the preset's menu swatch, so the swatch shows the preset's own colors.

#### Specificity

| Rule                           | Specificity | Matches                    |
| ------------------------------ | ----------- | -------------------------- |
| `:root` (default preset)       | 0,1,0       | Always                     |
| `:root[data-midux-preset="…"]` | 0,2,0       | When that preset is active |

- An active preset overrides the default.
- A preset may define **_only the variables that differ_**. The rest come from the default preset.
- So the default preset must define the complete palette.

#### Preset menu

`theme/theme.js` adds the presets to the Appearance Mode menu:

1. It applies the saved preset to `<html data-midux-preset="…">`.
2. A **MutationObserver** watches `#commonMenu` for `data-name="barmode"`.
3. It appends a separator and one item per preset, with a swatch. The active one is marked selected.
4. A click applies the preset, saves it and closes the menu.
5. `window.destroyTheme` disconnects the observer and removes the attribute.

| Setting     | Value                                       |
| ----------- | ------------------------------------------- |
| Storage key | `midux-preset` in `data/storage/local.json` |
| Attribute   | `data-midux-preset` on `<html>`             |
| Default     | `sepium`                                    |

#### Adding a preset

1. Create `src/presets/_<name>.scss` with `@include preset("<name>") { … }`.
2. Add `@use "presets/<name>";` to `src/theme.scss`.
3. Add `{ id: "<name>", label: "<Label>" }` to `PRESETS` in `theme/theme.js`.
4. Reload the SiYuan window. `theme.js` does not live-reload.

### Editor width

`src/_editor-width.scss` controls the side padding of the desktop editor.

**SiYuan's default:**

- The padding is **_stepped_**: it changes at fixed pane widths of 760, 952 and 2280px.
- So the text **_jumps_** sideways while you resize a pane or a dock, with **Adaptive Width** on or off.

**Midux goal:**

- **_Continuous padding:_** the text moves smoothly while resizing and never jumps.
- **Adaptive Width off:** the text width is **_capped_**, and the text is **_centered_** or left-aligned in the pane.
- **Adaptive Width on:** the text stays **_left-anchored_** with a fixed gutter. On wide panes, the right padding grows gradually, so long lines widen more slowly.
- Title, icon and tags row, database properties and bottom backlinks **_line up_** with the text. The cover image stays full-bleed.

**How it works:**

- Padding = gutter + a share of the free space beyond the text width. The pane width comes from `100cqi`, because SiYuan makes the editor a container.
- The partial redefines SiYuan's `--b3-protyle-padding-left/right`. SiYuan's own rules then apply them to every part of the document.
- The gutter, text width and alignment are variables in the partial's `:root` block. Override them in a **CSS snippet**.

> [!note]
> Only the desktop editor is affected. Mobile, the history viewer and the database row tab use inline padding set by SiYuan's JS.

### UI font sizes

`src/_ui-font.scss` sets the font size of the interface around the editor.

**SiYuan's default:**

- There is **_no setting_** for the interface font size. Settings → Editor changes only the document text.
- `--b3-font-size` reaches only menus and dialogs. Most other UI classes **_hard-code px sizes_**.
- Embedded editors in docks, such as Backlinks and Mentions, use the full document font size.

**Midux goal:**

- **_One adjustable scale:_** a few size steps (normal, small, tiny, micro) drive the whole interface instead of scattered px values.
- **Covered areas:** titlebar, breadcrumbs, dock panels and their titles, counters, menus and the Settings pane.
- **_Compact docks:_** dock panels and their embedded editors use a smaller size than the main editor.
- **_Row heights follow the font:_** list and menu rows grow and shrink with the text, so larger text never looks cramped.

**How it works:**

- The partial overrides SiYuan's hard-coded sizes with the **_same selectors_**. `theme.css` loads after SiYuan's CSS, so equal specificity wins.
- The size steps are variables in the partial's `:root` block. Override them in a **CSS snippet**.

### Subpixel text

`src/_opaque-layers.scss` keeps Chromium's subpixel (LCD) text in popup menus, the Settings pane and tab titles. For the background, the rendering settings and how to debug grayscale text, see [Text Rendering in SiYuan](30-text-rendering.md).

### Feature toggles (planned)

Not implemented yet. Toggles such as colored headings would follow the same pattern:

- **Attribute:** a presence attribute such as `data-midux-colored-headings` on `<html>`.
- **CSS:** each feature is scoped to its attribute, for example `:root[data-midux-colored-headings] .h1 { … }`. One partial per feature, such as `src/features/_colored-headings.scss`.
- **Storage:** one key per toggle, such as `midux-colored-headings`.
- **Menu:** a `TOGGLES` list in `theme.js`, rendered after the presets with its own separator. A click flips the attribute and the selected state. The menu can stay open.
- **Cleanup:** `destroyTheme` removes all `data-midux-*` attributes.

## Limitations

- **Light mode only.** In dark mode SiYuan uses `midnight`, and Midux is not active.
- **Startup flash:** with a non-default preset, the default shows briefly. `theme.js` runs after `theme.css`.
- **No live reload for `theme.js`.** Restart SiYuan or reload the window.
- **Mobile:** there is no sun menu, so the default preset applies.
- **Pop-out windows** pick up a preset change only after a reload.
